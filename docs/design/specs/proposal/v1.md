# Spec: Command proposal -- v1

> Normative specification. **Status: DRAFT (unstable -- will change).** This document uses
> [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) keywords: MUST, SHOULD, MAY.
> Decision record: ADR-0018.

## Motivation

The command model's answer is read by the REPL, by training (M3: the student must learn
this exact format) and by the eval runner (#81). A free-form answer would make each of
them guess.

## Scope

The JSON the command model returns for one natural-language request (`@request` and plain
natural-language input). Not covered: the prompt (a later spec with the prompts YAML,
#16), the reader's output (`reader-schema/v1`), the `@@` loop's step protocol (#76).

## Conventions

JSON as in RFC 8259, UTF-8. Lengths count Unicode code points.

## Requirements

1. The response MUST be one JSON object matching this schema, enforced by constrained
   decoding (ADR-0018):

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["kind"],
  "properties": {
    "kind": { "enum": ["command", "clarify", "refuse"] },
    "command": { "type": "string", "minLength": 1, "maxLength": 2000 },
    "risk": { "enum": ["read-only", "mutating", "session-altering", "destructive", "privileged"] },
    "reason": { "enum": ["unclear-request", "not-a-shell-task", "unsafe-request", "missing-information"] }
  }
}
```

2. `kind = "command"` MUST have `command` and `risk`, and MUST NOT have `reason`.
   `kind = "clarify"` or `"refuse"` MUST have `reason` and MUST NOT have `command`.
3. `command` is one bash command line; lists and pipelines are allowed, as are newlines
   (a multi-line command). It is classed by the policy gate (spec `policy-gate/v1`) like
   any other command. `risk` can only raise the gate's class (ADR-0013 §8).
4. There is no free-text explanation field. The REPL explains with its own templates, and
   `?` (ask mode) is a separate request.
5. A response that fails to parse, fails the schema, or breaks rule 2 MUST be rejected.
   The REPL MUST NOT repair it.

## Versioning and compatibility

Adding an enum value to `reason` is compatible. Any change to `command`, `risk` or `kind`
requires v2 and retraining (M3).

## Conformance

The parser tests (#16, #77) MUST include: each valid shape; extra properties; a missing
`risk`; `command` with `reason`; an over-long `command`; invalid JSON; a JSON array; and a
`risk` lower than the gate's class (the gate's class wins).

## Open questions

- Whether `clarify` should carry a fixed-choice question type so the REPL can ask a
  templated follow-up.
