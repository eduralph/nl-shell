# Spec: Policy gate -- v2

> Normative specification. **Status: DRAFT (unstable -- will change).** This document uses
> [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) keywords: MUST, SHOULD, MAY.
> Decision records: ADR-0027 (the grammar; supersedes ADR-0013), ADR-0015 (sudo rules),
> ADR-0016 (taint effects), ADR-0023 (OS targets), ADR-0025 (sensitive paths).

## Motivation

The gate is the one deterministic decision between a model's proposal and the user's
system. The REPL, the tests (#12), the threat model and the security-review leaf must all
agree on exactly what it does. A change here changes what runs without a confirm, so it
is versioned and reviewed as a contract.

v2 replaces v1's premise. v1 parsed arbitrary bash with tree-sitter-bash and had to prove
the tree faithful to bash for the whole language before any `read-only` decision was
sound; that proof had no closing condition (ADR-0027). v2 grants `read-only` only inside
a closed grammar whose recogniser is sound by construction, decides rejections and the
`privileged` class by an over-approximating text scan, and treats everything else as a
command the user confirms as written. The allowlist, live-session resolution and the
sensitive-path rules are unchanged from v1.

## Scope

Covers: the classes, the decision procedure, the read-only grammar, the text scan, the
read-only allowlist format and initial entries, live-session resolution, the advisory
layer, outright rejections, and conformance vectors. Does not cover: what the confirm UI
shows (#74), taint effects (ADR-0016), or how the session snapshot is produced (spec
`pty-protocol`).

The procedure is the same on every OS. What differs per OS (the allowlist, the
package-owner query and the conformance vectors) comes from the active target (ADR-0023).

## Conventions

- *Command*: the full text the user would confirm, possibly a list or pipeline.
- *Simple command*: one command word with its arguments and redirections.
- *Command word*: the first word of a simple command after quote removal.
- *Snapshot*: the latest session snapshot (spec `pty-protocol` §3) and its baseline.
- Classes, lowest to highest: `read-only` < `mutating` = `session-altering` <
  `destructive` < `privileged`. *At least X* means the higher of the current class and X.
- *Rejected* means the command cannot be confirmed or run at all.
- *Target*: the active OS target, `targets/<id>/` (ADR-0023).
- *System directories*: `/usr/bin`, `/usr/sbin`, `/bin`, `/sbin`.
- *Package-owned*: owned by an installed package according to the target's package-owner
  query (`target.toml`; `dpkg -S` on `ubuntu-26.04`).
- *Blanked text*: the command with the inside of every closed single-quoted run replaced
  by spaces and every backslash-newline outside single quotes removed. An unclosed quote
  stays as written.

## Requirements

### 1. Decision procedure

The gate MUST compute a command's class as follows, and the result MUST be the highest
class produced by any step. Steps 2, 4 and 5 are independent of one another; none of them
reads another's result.

1. **Characters.**
   - A model proposal containing C0 control characters (except TAB and LF inside quotes),
     `ESC`, C1 controls, or bidi or zero-width characters (U+200B–U+200F, U+202A–U+202E,
     U+2060–U+2069, U+FEFF) is **rejected**. An implementation MAY apply this inside
     quotes too.
   - Typed input with them is shown escaped and is at least `mutating`.
2. **Text scan** (§4, §5): the outright rejections and the `privileged` class, decided
   over the blanked text.
3. **The read-only grammar** (§2). If the command is not in the grammar, it is at least
   `mutating`, reason "outside the read-only grammar", and steps 3a–3c are skipped: the
   gate MUST NOT try to establish `read-only` for it by any other means. If it is in
   the grammar, then for every simple command, in source order:
   - 3a. the command layer (§3): the allowlist and the per-command rules;
   - 3b. live-session resolution (§7) for a simple command still `read-only`;
   - 3c. sensitive locations (§8).
4. **Advice** (§6): the tree-sitter walk. Its findings MAY raise the class and add
   reasons; they MUST NOT lower it, grant `read-only`, or reject. A walk that fails
   contributes nothing.
5. **Model label:** if the model labelled its proposal higher than the result, use the
   label. Never lower.

A simple command no allowlist entry matches is `mutating`, reason "not allowlisted".

### 2. The read-only grammar

The grammar is closed. A recogniser for it MUST accept exactly the strings below and
MUST NOT depend on a general-purpose shell parser.

```
list      := pipeline ( ( "||" | "&&" | ";" ) pipeline )* [ ";" ]
pipeline  := simple ( "|" simple )*
simple    := ( word | redirect )+             -- at least one word
redirect  := "2>&1" | [ "2" | "&" ] ">" ws* "/dev/null" | "<" ws* word
word      := piece+                           -- adjacent pieces form one word
piece     := bare | "'" [^'\n]* "'" | '"' [^"$`\\!\n]* '"'
bare      := [A-Za-z0-9_./:@%+,=-]+
ws        := " " | "\t"
```

Tokens are separated by spaces and tabs only. Further rules:

1. The command word MUST NOT contain `=` in any piece and MUST NOT be empty after quote
   removal. A command word that is a single bare piece spelling a bash reserved word
   (`if then else elif fi do done case esac while until for in select function time
   coproc`) is outside the grammar.
2. A digit run written immediately before `<` or `>` is a descriptor for bash, not a
   word; only the four redirect spellings above are accepted, so `22>&1`, `2>&2`,
   `1>&2`, `>&2` and `>> /dev/null` are outside the grammar.
3. Nothing else is accepted. In particular: `~`, `*`, `?`, `[`, `{`, `}`, `$`,
   backtick, `#`, `!`, `\`, `&`, `(`, `)`, newline, `|&`, `;;`, here-documents,
   here-strings, process substitution, prefix assignments, function definitions,
   compound commands, and a redirect to any file.
4. Input over 8 KiB is outside the grammar.

The grammar produces, per simple command: its words after quote removal (all literal),
its redirects, and its stdin: `file` (the `<` operand) when a `<` is present, else
`terminal` for the first command of a pipeline and `pipe` for the others. These feed
§3, §7 and §8.

**Why this is sound.** For a string the grammar accepts, bash performs no expansion
(there is nothing to expand), no word splitting beyond the separators the recogniser
splits on, and quote removal only (the recogniser strips the same quotes). So the words
the recogniser produces are the words bash runs. The conformance test for this
property compares the recogniser against bash itself (Conformance).

**Extending the grammar** (ADR-0027 point 6) is a spec change: `~`, globs and variables
are the known candidates, each needing gate-side expansion against the snapshot's cwd and
`HOME` so §8 sees the resolved operands. An extension MUST keep the soundness argument
above true for the extended language.

### 3. The command layer

For each simple command the grammar produced:

1. **The read-only allowlist** (§3.3) decides whether the command word, its options and
   its operands are a known read-only shape. Any option or subcommand not listed, or an
   unknown command word, makes the simple command `mutating`, "not allowlisted".
2. **Per-command rules**, each ⇒ at least `mutating`:
   - the words `/dev/tcp/…` or `/dev/udp/…` anywhere, in a word or a redirect target;
   - an input redirection (`<`) from anything that is not an existing regular file at
     classification time;
   - a file operand of an allowlisted command that reads file contents (every entry whose
     operand shape is "file operands") that, after `realpath`, is not an existing regular
     file at gate time. A directory is allowed only for entries that walk directories
     (`ls`, `du`, `find` without actions, `tree`). A character or block device, FIFO,
     socket, or a path that does not exist makes the command at least `mutating`;
   - a command word that is a path (contains `/`) outside the package-owned system
     directories;
   - a simple command that reads the terminal: a command whose allowlist entry is marked
     `stdin` and that has no file operand and no input redirection, at the start of a
     pipeline or standing alone (ADR-0015: no keyboard sinks).
3. **The allowlist** MUST live in one data file per target, `targets/<id>/allowlist.toml`,
   versioned with this spec. The gate MUST use only the active target's file. A target
   MUST NOT inherit or fall back to another target's allowlist; a new target starts
   empty, so everything on it is at least `mutating` until entries are reviewed in.
   Each entry names a command word and MAY give:
   - `flags`: allowed options without values;
   - `options`: allowed options with a value;
   - `subcommands`: allowed first operands;
   - `max_operands`;
   - `stdin = true` if the command reads standard input when given no file operand.

   Nothing that can open a network connection, run another program, write a file, or
   change system state MAY be on the allowlist. The initial entries for `ubuntu-26.04`
   are those of v1 §6.4, unchanged:

| Command | Allowed shape (summary) | Notes |
|---|---|---|
| `ls`, `tree`, `stat`, `file`, `realpath`, `readlink`, `basename`, `dirname`, `pwd` | listing/format flags; paths | — |
| `cd`, `pushd`, `popd`, `dirs` | one path | changes cwd only |

   or `git log` can run commands from the repository's own config (`core.fsmonitor`,
   `core.pager`, hooks). `awk`, `sed`, `find`, `xargs`, `watch`, `timeout` are not on it
   either, because each can run commands.

### 4. The text scan: `privileged`

Over the blanked text, a command is at least `privileged` when one of `sudo`, `su`,
`pkexec`, `doas`, `run0`, `machinectl` stands as a word: at the start, or after a
space, tab, `;`, `|`, `&`, `(`, `)`, `{`, `}`, backtick, `$`, `"` or `\`, optionally
with a path in front (`/usr/bin/sudo`), and followed by the end, a space, tab, `;`,
`|`, `&`, `(`, `)`, `{`, `}`, backtick, `<`, `>` or `"`. This over-approximates
(`grep sudo file` is `privileged`); that is intended.

The inner command of `sudo`/`doas` is also classed by §6 and the result is never below
`privileged`.

### 5. The text scan: rejected

Over the blanked text, a command is **rejected** (cannot be confirmed, proposals and typed
input alike unless stated) when any of the following matches. Each pattern is an
over-approximation: anything that *could* be the construct counts.

1. **Descriptors 3 and above** (fd 3 is nl-shell's control channel, ADR-0014; ADR-0028
   makes records from other processes detectable, but the same-process case is this
   rule's):
   - a digit run of value ≥ 3 written immediately before `<` or `>` and not preceded by
     a word character, `.`, `{` or `-` (`3>x`, `12<x`, `3>&-`, `2026>x`; not `a3>f`,
     `-1>x`, `file.3>x`);
   - `{name}` immediately before `<` or `>`;
   - `>&` or `<&` followed by optional spaces, an optional `"`, and a digit run of value
     ≥ 3;
   - `/dev/fd/N` or `/proc/<anything>/fd/N` anywhere with N ≥ 3;
   - a redirect operator followed by optional spaces, an optional `"`, and either a
     bare digit run of value ≥ 3 or a path ending in `fd/N` with N ≥ 3 (the cwd may be
     `/dev/fd`).
2. **sudo and doas options**, read from the text after the word with every quote
   character and backslash removed (`sudo '-S'` is `sudo -S`): walking the tokens up to
   the inner command, where `-C -D -g -h -p -r -t -T -u -U` take a value, a short option
   cluster containing `S`, `A` or `p`, or a long option `--stdin`, `--askpass` or
   `--prompt`, rejects; a token containing `$` or a backtick before the inner command
   rejects ("an argument the gate cannot read"); `-s`, `-i`, `--shell` or `--login`
   together with a `|` or `<<` anywhere in the command rejects.
3. **A pipe into a privileged word**: the text before the word, trailing spaces
   removed, ends in `|` but not `||`.
4. **A here-document or here-string in a command that has a privileged word**: `<<`
   anywhere.
5. **`SUDO_PROMPT` or `SUDO_ASKPASS`** anywhere in the command with every quote
   character and backslash removed (`export S'UDO_PROMPT'=x`).
6. **A declaration with an operand bash names only after expansion**: `export`,
   `declare`, `typeset`, `readonly` or `local` followed by a `$` or backtick before the
   next `;`, `|` or `&`.
7. **Model proposals** only: a root shell — `sudo`/`doas` with `-s`, `-i`, `--shell` or
   `--login`, or whose inner command is `bash`, `sh`, `zsh`, `dash`, `fish`, `ksh`,
   `csh`, `tcsh` or `su`; `su` without `-c`; `pkexec` with a shell as its inner command.
   Typed input doing this is `privileged`, and the session runs it in full passthrough
   until it exits (ADR-0015).
8. Model proposals with forbidden characters (§1.1).

The scan MUST NOT raise; an internal failure of the scan rejects the command.

### 6. Advice

The gate MAY parse the command with tree-sitter-bash and walk the tree to raise the
class and word the confirm. The walk's findings are advisory: a parse error, an
unhandled construct, a size or work bound or any internal error ends the walk with no
findings, and the command is confirmed as whatever §1–§5 made it. The walk MUST NOT
grant `read-only` and MUST NOT be the only detector of a §5 rejection.

What the walk reports when it runs:

- ⇒ at least `session-altering`: a function definition; the builtins `alias`,
  `unalias`, `source`, `.`, `eval`, `exec`, `trap`, `enable`, `set`, `shopt`, `bind`,
  `complete`, `hash`, `builtin`, `command`, `export`, `declare`/`typeset`/`local`/
  `readonly`, `unset`; any assignment (standalone, exported or prefix) to `PATH`,
  `BASH_ENV`, `ENV`, `CDPATH`, `PROMPT_COMMAND`, `PS0`–`PS4`, `IFS`, `HISTFILE`,
  `LD_*`, `PAGER`, `MANPAGER`, `SYSTEMD_PAGER`, `GIT_PAGER`, `LESSOPEN`, `LESSCLOSE`,
  `EDITOR`, `VISUAL`, `BROWSER`, `SUDO_*`, `PYTHON*`, `PERL5*`, `NODE_OPTIONS`, `GIT_*`.
- ⇒ at least `destructive`: `rm` with `-r`/`-R`/`--recursive` or a glob operand; `dd`;
  `mkfs*`; `wipefs`; `shred`; `truncate`; `fdisk`/`sfdisk`/`parted`/`gdisk`; `chmod`/
  `chown` with `-R`; `find … -delete`; `git clean`; `git reset --hard`; `git push
  --force`/`-f`/`--force-with-lease`; `systemctl` `disable|mask|stop|kill|isolate|
  poweroff|reboot|halt`; `kill -9 -1`.
- ⇒ at least `mutating`, with the reason: a prefix assignment; an output redirection
  other than `>/dev/null`, `2>&1`, `1>&2`, `>&2`; process substitution; a command word
  that is not a literal after quote removal; `/dev/tcp` or `/dev/udp`; a wrapper (`env`
  with a command, `nice`, `nohup`, `timeout`, `time`, `xargs`, `watch`, `command`,
  `builtin`, `find -exec/-execdir/-ok/-okdir`, `bash -c`/`sh -c`), whose inner command
  is classed by the same rules, looking through the wrapper's own options and `env`'s
  assignments.

### 7. Live-session resolution

For each simple command still `read-only` after §3, the gate MUST check against the
snapshot:

1. If the command word is an alias in `L`, expand it (recursively, as bash does, stopping
   at a repeated name). The expansion MUST itself be in the read-only grammar (§2) — else
   the simple command is `mutating`, reason "alias expands outside the read-only
   grammar" — and is classed with §3. The result replaces the original.
2. If the command word is a function name in `F` ⇒ `mutating`, reason "function".
3. If it is a builtin, it MUST NOT be disabled in `B`; else ⇒ `mutating`.
4. Otherwise resolve it against `P` (the snapshot's `PATH`). The first match MUST be a
   regular executable in the system directories and package-owned (the target's
   package-owner query, cached). Otherwise ⇒ `mutating`, reason "not a system command".
5. `T` MUST show no `DEBUG`, `RETURN` or `ERR` trap that the baseline didn't have; `X` MUST
   show `extdebug` off; `H` MUST equal the baseline; the pager and loader variables
   (`V`, the encoded `declare -p` text of `PAGER`, `MANPAGER`, `SYSTEMD_PAGER`,
   `GIT_PAGER`, `LESSOPEN`, `LESSCLOSE`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, `BASH_ENV`,
   `ENV`, pty-protocol §3) MUST equal the baseline exactly. Any difference ⇒ the whole
   command is `mutating`, reason "session changed".
6. A missing snapshot ⇒ degraded mode (pty-protocol §4): no command is sent to the
   session until it is restarted. This session degraded mode (refuse) is not the
   gate-level target-mismatch state of item 7.
7. An active target that does not match `/etc/os-release` (the user named it, ADR-0023)
   ⇒ degraded mode: everything `mutating`, reason "target does not match this OS".

The confirm MUST show the reason whenever §7 raised the class.

### 8. Sensitive locations

The target lists sensitive locations in `targets/<id>/sensitive.toml` (ADR-0023,
ADR-0025): `paths` (prefixes), `names` (file-name patterns) and `env_dumpers`.

1. The gate MUST resolve every file operand with `realpath` against the session cwd,
   following symlinks. A simple command is at least `mutating` when a resolved operand,
   or a glob's directory part, is under a listed path or has a name matching a listed
   pattern.
2. A recursive reader (`grep -r`/`-R`, `cat` or another reader via `find -exec`, `tar`,
   `rsync`, `cp -r`) is at least `mutating` when an operand is an ancestor of a listed
   path.
3. The confirm MUST name the matched location (e.g. "reads ~/.ssh").
4. The output of a command matched by 1 or 2, and of a command listed in `env_dumpers`,
   is labelled `secret` (ADR-0016). An `env_dumpers` entry does not change the class.
5. Matching is by path, never by content. This applies to proposals and typed input
   alike.
6. Paths under `/proc/<pid>/` (including `/proc/self/`) other than `status`, `stat` and
   `limits` are sensitive on every target, whether or not `sensitive.toml` lists them:
   `environ` holds secrets and `mem` is process memory.

The gate checks file types and paths at gate time, and the command runs a moment later.
That gap is accepted: changing a file's type in between needs code running as the user,
which is out of scope.

## Versioning and compatibility

Adding an allowlist entry, raising a class, or adding a §5 pattern is a compatible change
within v2 but MUST be reviewed by a human (nl-shell-pdca INTEGRATION §4). Adding a target
is compatible; each entry in its allowlist is reviewed the same way, even when copied
from another target. Extending the grammar (§2), lowering any class, removing a rule from
§3–§5, or changing §7 requires v3.

Against v1: every v1 `read-only` outcome that used `~`, a glob or an expansion is now
`mutating` ("outside the read-only grammar"); v1's "unparseable" reason is gone; v1's
rejections on non-literal redirect targets (`>"$f"`, `> >(cmd)`) are now confirms with
the target shown, since §5.1 catches the descriptor spellings whatever the target; the
differential-parser requirement is dropped.

Rows 35 and 36 test the confirm, not the class: the cached-credentials warning (ADR-0015
point 6) is part of the confirm and never changes a command's class. Rows 37–41 use
absolute paths because `~` is outside the grammar; the v1 forms with `~` are
`mutating` ("outside the read-only grammar").

Besides the vectors, the gate's tier-0 tests MUST include:

- **The bash oracle (tier 0).** A generator produces strings from the grammar's
  vocabulary (bare words, quoted words, adjacent pieces, the four redirects, `|`, `;`
  and `&&`). For every string the recogniser accepts, bash runs it with the command
  words bound to functions that record their arguments, and the recogniser's words per
  simple command MUST equal the recording, and bash MUST exit 0. This is the whole
  soundness test for §2; there is no second parser.
- **Scan coverage (tier 0).** Every spelling listed in §5 has a rejected case, and the
  listed non-matches (`a3>f`, `-1>x`, `file.3>x`, `grep '3>' f`, `cmd || sudo x`,
  `sudo cp -p a b`) have a not-rejected case.

## Open questions

- Whether `cd` into a directory with an `.envrc` (direnv) should be `mutating`: direnv only
  loads allowed `.envrc` files, so v2 keeps `cd` read-only.
- Output rendering: read-only commands like `cat` and `echo` can print terminal escape
  sequences (OSC 52 clipboard writes, title changes). The mirror filter is part of the
  threat-model revision (#71) and the PTY spec.
- The first grammar extension. The eval runner (#81) reports how often a proposal for a
  read task falls outside the grammar and which construct it used; `~` and `$HOME` are
  the expected leaders.
