# Spec: PTY session protocol -- v1

> Normative specification. **Status: DRAFT (unstable -- will change).** This document uses
> [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) keywords: MUST, SHOULD, MAY.
> Decision record: ADR-0014.

## Motivation

The REPL, the policy gate (spec `policy-gate/v1`) and the sudo handling (ADR-0015) all
depend on knowing exactly when a command starts and ends, its exit status, and the state
of the bash session. That knowledge must not be forgeable by anything a command prints.

## Scope

Covers: how the session is started, the control-channel record format, the session
snapshot, how a confirmed command is sent, terminal ownership while a command runs, and
degraded mode. Does not cover: what is classed how (policy-gate spec), sudo prompt
handling (ADR-0015), or what captured output is used for (taint, ADR-0016).

## Conventions

- *Session*: one bash process on a PTY, started by nl-shell, for the life of the REPL.
- *Control channel*: a pipe whose write end is file descriptor 3 in the session.
- *Record*: one line on the control channel, `\n`-terminated, fields separated by one
  space, first field a one-letter type.

## Requirements

### 1. Starting the session

1. nl-shell MUST start `bash --noprofile --rcfile <rcfile> -i` on a PTY, with the write end
   of a pipe as fd 3 in the child and the read end kept by nl-shell.
2. The rcfile MUST source the user's `~/.bashrc` (if present) **before** installing
   nl-shell's hooks, and MUST:
   - turn off history expansion (`set +H`);
   - unset `HISTFILE` (nl-shell writes history itself, ADR-0014 §5);
   - save any `PROMPT_COMMAND` set by `~/.bashrc` (every element) and run it at every
     prompt after the `D` record and **before** the snapshot, so the snapshot sees what it
     changed; nl-shell's hook is the last `PROMPT_COMMAND` element;
   - set `PS1` and `PS2` to fixed values after the user's `PROMPT_COMMAND` and again after
     the snapshot, unless a command gave them attributes (such as `readonly`), which `H`
     shows (§3);
   - set `PS0` and `PROMPT_COMMAND` as in the reference rcfile below.
3. Reference rcfile (tested on Ubuntu 26.04, bash 5.3.9; `src/nl_shell/session.py`
   `RCFILE`, and `tests/test_session.py` checks the two are the same):

```bash
[ -f ~/.bashrc ] && . ~/.bashrc
set +H
unset HISTFILE
bind 'set enable-bracketed-paste on' 2>/dev/null
shopt -s promptvars
__nls_ea=$(shopt -p expand_aliases); shopt -u expand_aliases
__nls_user_pc=()
if declare -p PROMPT_COMMAND >/dev/null 2>&1; then __nls_user_pc=("${PROMPT_COMMAND[@]}"); fi
__nls_seq=-1 __nls_st=0 __nls_ps=() __nls_v= __nls_c= __nls_n=0 __nls_pre=
PS0='$(\\builtin printf "S %s\\n" "$((__nls_seq + 1))" >&3)'
__nls_ret() { \builtin return "$1"; }
__nls_enc() {
  __nls_v=$2
  __nls_v=${__nls_v//'\'/'\\'}
  __nls_v=${__nls_v//$'\n'/'\n'}
  __nls_v=${__nls_v//$'\r'/'\r'}
  \builtin printf '%s %s\n' "$1" "$__nls_v" >&3
}
__nls_done() {
  \builtin set -- "$?" "${PIPESTATUS[@]}"
  __nls_pre=$(\builtin declare -p __nls_pre __nls_c __nls_n __nls_ps __nls_st __nls_v 2>&1) ||
    \builtin :
  __nls_st=$1
  \builtin shift
  __nls_ps=("$@")
  \builtin printf '\033]7700;@NLS_END@\007'
  __nls_seq=$((__nls_seq + 1))
  \builtin printf -v __nls_v ' %s' "${__nls_ps[@]}"
  \builtin printf 'D %s %s%s\n' "$__nls_seq" "$__nls_st" "$__nls_v" >&3
  for __nls_c in "${__nls_user_pc[@]}"; do
    if __nls_ret "$__nls_st"; then
      \builtin eval "$__nls_c" || \builtin :
    else
      \builtin eval "$__nls_c" || \builtin :
    fi
  done
  __nls_st=0 __nls_ps=() __nls_v= __nls_c= __nls_n=0
}
__nls_snap() {
  \builtin set -- "$1" "${BASHOPTS-}"
  \builtin shopt -u expand_aliases
  for __nls_c in PS1 PS2; do
    __nls_v=$(\builtin declare -p "$__nls_c" 2>/dev/null) || __nls_v=
    if [[ -z $__nls_v || ${__nls_v%%=*} == "declare -"[-x]" $__nls_c" ]]; then
      if [[ $__nls_c == PS1 ]]; then PS1='\$ '; else PS2='> '; fi
    fi
  done
  __nls_v= __nls_c=
  __nls_enc H "$( {
    \builtin declare -p PS0 PROMPT_COMMAND __nls_user_pc TERM PS1 PS2
    \builtin shopt -p promptvars
    for __nls_c in __nls_c __nls_done __nls_ea __nls_enc __nls_n __nls_pre __nls_ps __nls_ret __nls_seq __nls_snap __nls_st __nls_user_pc __nls_v; do
      \builtin declare -p "$__nls_c" 2>/dev/null || \builtin printf '%s unset\n' "$__nls_c"
    done
    \builtin declare -f __nls_done __nls_snap __nls_enc __nls_ret
  } 2>&1 )"
  __nls_enc V "$(
    for __nls_c in PAGER MANPAGER SYSTEMD_PAGER GIT_PAGER LESSOPEN LESSCLOSE LD_PRELOAD LD_LIBRARY_PATH BASH_ENV ENV; do
      \builtin declare -p "$__nls_c" 2>/dev/null || \builtin printf '%s unset\n' "$__nls_c"
    done
  )"
  __nls_enc F "$(\builtin compgen -A function)"
  __nls_enc L "$(\builtin alias -p)"
  __nls_enc T "$1"
  __nls_enc B "$(\builtin enable -n)"
  __nls_enc X "$(\builtin shopt -p extdebug)"
  __nls_enc P "${PATH-}"
  __nls_v=$(\builtin jobs -ps) __nls_n=0
  if [[ -n $__nls_v ]]; then __nls_c=${__nls_v//[!$'\n']/}; __nls_n=$((${#__nls_c} + 1)); fi
  \builtin printf 'J %s\n' "$__nls_n" >&3
  __nls_st=0 __nls_ps=() __nls_v= __nls_c= __nls_n=0 __nls_pre=
  \builtin printf 'E\n' >&3
  PS1='\$ ' PS2='> '
  if [[ :$2: == *:expand_aliases:* ]]; then \builtin shopt -s expand_aliases; fi
}
\builtin unset PROMPT_COMMAND
PROMPT_COMMAND=('' '\__nls_done; \__nls_snap "$(\builtin trap -p)"')
builtin eval "$__nls_ea"; builtin unset __nls_ea
```

   The hooks call no external program, only bash builtins and parameter expansion.
   `PS0` writes `\\n` because bash decodes prompt escapes before expanding `PS0` and would
   turn `\n` into CR LF. `PROMPT_COMMAND` element 0 is empty (it keeps `$?` and
   `PIPESTATUS`), so `PROMPT_COMMAND=:` replaces it and leaves nl-shell's hook in place.
   `@NLS_END@` is replaced by a random token at every start: `__nls_done` prints that OSC
   sequence on the PTY before it writes `D` and before the user's `PROMPT_COMMAND` runs,
   and a command's output is what follows readline's end of the paste (`ESC [?2004l`) and
   precedes that marker. The hooks are safe under `set -u` and `set -e`.

   **What this protects.** This is a closed list; nothing else is claimed yet (#141,
   #145).
   - A command that ran is never reported as "nothing ran" while the session stays
     healthy, for: ordinary commands; a confirmed command that changes anything `H`
     covers (§3), which degrades at that command's own snapshot; a `PS1` that assigns hook
     state as a side effect, `readonly` on hook state, and a top-level `trap … DEBUG`
     that assigns hook state; and user aliases, which cannot change what the hooks run
     (every command word in `PS0`, `PROMPT_COMMAND` and `__nls_done` is `\builtin`-quoted,
     and `__nls_snap` runs its `$( … )` bodies with `expand_aliases` off).
   - Of `PROMPT_COMMAND`, `PS0`, `PS1` and `PS2`: nl-shell's hook is the last
     `PROMPT_COMMAND` element, the user's elements from `~/.bashrc` run inside it before
     the snapshot, and a confirmed change to the value of a plain or exported `PS1`/`PS2`
     is overwritten by nl-shell before it is shown. A confirmed change to `PS0` or
     `PROMPT_COMMAND`, or to the attributes of `PS1`/`PS2` (such as `readonly`), degrades
     at that command's own snapshot (`H`), but the code it set may still run once after
     that snapshot, before nl-shell refuses further commands. Other routes that run code
     after the snapshot (readline `bind -x`, a top-level DEBUG trap around
     `PROMPT_COMMAND` elements, `PS4`/xtrace) are not claimed.

### 2. Records

| Record | Written by | Fields | Meaning |
|---|---|---|---|
| `S <n>` | `PS0` | sequence number of the command about to run | a command started |
| `D <n> <status> <pipestatus…>` | `PROMPT_COMMAND` | sequence number, `$?`, `PIPESTATUS` | the command finished, or nothing ran (§4.1) |
| `F <names>` | `PROMPT_COMMAND` | `compgen -A function` output, encoded | function names, one per line |
| `L <defs>` | `PROMPT_COMMAND` | `alias -p` output, encoded | alias definitions |
| `E` | `PROMPT_COMMAND` | — | end of this snapshot |

The first snapshot (before any command) has sequence number 0 and no `S` record.

Every free-text field (`F`, `L` and the §3 text fields) uses one reversible encoding: `\`
is written `\\`, LF `\n` and CR `\r`; no other escape exists, so a record never holds a
raw LF or CR. A record that contains a CR, or a bad escape, is malformed.

### 3. Snapshot (v1 fields)

Besides `F` and `L`, a v1 snapshot MUST carry, as separate record types before `E`:
`T` (output of `trap -p`), `B` (output of `enable -n`, i.e. disabled builtins), `X`
(`shopt -p extdebug`), `P` (`$PATH`), `J` (number of stopped jobs, counted from
`jobs -ps` with builtins only), `H` and `V`. nl-shell records the first snapshot as the
session's **baseline**.

`H` and `V` carry raw `declare -p` (and builtin) output text, encoded as in §2, and are
compared exactly; there is no checksum.

- `H` covers nl-shell's prompt hooks and their state: `declare -p` of `PS0`,
  `PROMPT_COMMAND` (every element), the saved user hook, `TERM` (readline turns bracketed
  paste off for some terminals), and `PS1` and `PS2` as nl-shell set them; `shopt -p
  promptvars`; `declare -p` of every hook state variable, value and attributes (so
  `readonly` too; `NAME unset` when it is not a variable); and `declare -f` of the hook
  functions. The hooks overwrite their scratch variables, so `__nls_done` first saves
  their `declare -p` text in `__nls_pre` (part of `H`) and `__nls_snap` resets them before
  `E`; a confirmed change to their value or attributes shows in that command's `H`. The
  only value that changes between snapshots is the sequence counter, which MUST equal the
  `D` record's number. Everything else MUST equal the baseline byte for byte.
- `V` is `declare -p` of the pager and loader variables listed in spec `policy-gate/v1`
  §7.5 (`NAME unset` when unset).

### 4. Sequencing and degraded mode

1. After sending a command, nl-shell MUST see `S n+1`, then `D n+1 …`, then a snapshot
   ending in `E`, in that order. Output on the PTY between `S` and `D` belongs to that
   command; it includes bash's own job notices (`[1]+  Done …`), which bash prints before
   its next prompt, so a background job's notice lands in the output of a later command.
   `PS0` runs once per line of a multi-line command, so `S n+1` MAY repeat before `D n+1`.
   `D n+1` without `S n+1` means bash read the input but ran nothing (an empty line, a
   comment, a syntax error): it is reported as not run with the `D` status, and the
   session stays healthy.
2. nl-shell MUST enter **degraded mode** when:
   - a record is missing, out of order or malformed (except `D n+1` without `S n+1`,
     §4.1);
   - the control channel closes;
   - from the paste, no `D` has arrived and bash has been blocked reading fd 0 (read from
     `/proc/<bash pid>/syscall`; fd 0 is the session's PTY slave or `/dev/tty`, so a
     builtin reading a redirected fd 0 does not count) for 1 s continuously: "no done
     record after the shell returned to a prompt". nl-shell does not parse the PTY stream
     for prompts. If `/proc/<bash pid>/syscall` cannot be read, at start or during a
     command, the session degrades with a reason naming the file. Known limits (#136): a
     terminal read on another fd (`read -u 2 x`) is not seen, so a `run()` with no
     timeout can wait forever; timed or single-key reads (`read -t`, `read -n1 -t`) and
     `select` degrade even when they would finish;
   - the snapshot's `H` differs from the baseline (nl-shell's hooks were changed); this is
     found at the snapshot of the command that changed them.
3. In degraded mode nl-shell MUST NOT send the session any further command until it is
   restarted. The user MUST be told why, and nl-shell MUST offer to restart the session.
4. **Session recovery.** When bash exits unexpectedly or the user accepts a restart,
   nl-shell starts a new session and restores the last cwd with a visible, logged
   `cd -- <path>` if that path still exists. Shell variables, aliases, functions and jobs
   are not restored; nl-shell says so in one line. Restoring the cwd lands with #121;
   until then a restart gives a fresh session and baseline only.
5. The session log records the restart as a turn with `"decision": "none"` and the field
   `"event": {"type": "session_restart", "reason": …}`, where the reason is `exited`,
   `degraded` or `user` (spec `session-log/v1`). This record lands with #121.

### 5. Sending a command

1. nl-shell MUST send exactly the confirmed bytes as one bracketed paste
   (`ESC [200~` … `ESC [201~`) followed by a single `CR`.
2. A command containing `ESC`, any other C0 control character except TAB and LF, or the
   byte sequence `ESC [201~` MUST NOT be sent (the policy gate rejects it first).
3. Nothing else may be sent to the session while a command runs, except forwarded
   keystrokes (§6).

### 6. Terminal ownership

1. Between sending a command and its `D` record, nl-shell MUST put the real terminal in
   raw mode and forward every input byte to the PTY master unchanged, and MUST NOT log,
   capture or keep any forwarded input byte.
2. nl-shell MUST copy PTY output to the real terminal and MAY capture it for the state
   block, subject to:
   - capture MUST stop on `ESC [?1049h` / `ESC [?47h` (alternate screen) and resume on
     the matching reset;
   - capture MUST stop during sudo passthrough (ADR-0015).
3. On `SIGWINCH`, nl-shell MUST copy the real terminal's size to the PTY.
4. Ctrl-C, Ctrl-Z and other control keys travel as bytes; nl-shell MUST NOT intercept
   them while a command runs.
5. At the prompt (after `E`), prompt_toolkit owns the terminal.
6. **Background output.** A job started earlier with `&`, or a process still attached to
   the PTY, can keep writing while prompt_toolkit owns the terminal. Its output could cover
   the confirm or imitate a confirm or a sudo prompt, so:
   - Between a done record and the next start record (prompt_toolkit owns the terminal),
     bytes read from the PTY MUST NOT reach the screen directly. nl-shell buffers them, up
     to 64 KiB, dropping the oldest bytes beyond that and saying how many were dropped.
   - The buffer is shown above the prompt, through the same output filter as mirrored
     output, under a line `[background output]`, when the user is not in a confirm and not
     editing a line, or on `:jobs`.
   - During a confirm the buffer is never shown. The confirm shows a one-line notice
     "background output waiting" instead, so the user knows something is running.
   - Background output is labelled untrusted and is never added to the state block.

   The 64 KiB limit is a starting value, to be adjusted after M0 dogfooding.

### 7. History

nl-shell MUST append each executed command to `~/.bash_history` itself, after the `D`
record, and record the turn's taint in the session log (ADR-0016). The session MUST NOT
write history.

## Versioning and compatibility

Adding a snapshot record type is compatible within v1 if nl-shell ignores unknown types.
Changing a record's fields, the paste framing or the start-up command requires v2.
While this spec is `status: draft`, v1 changes in place; the v2 rule applies once it is
`stable`.

## Conformance

The session tests for #10 (#101, #102, #120, #121) MUST cover at least these vectors:

| # | Sent | Expected on the control channel / behaviour |
|---|---|---|
| 1 | `true` | `S 1`, `D 1 0 0`, snapshot, `E` |
| 2 | `false \| true` | `D … 0 1 0` |
| 3 | `(exit 3)` | `D … 3 3` |
| 4 | `printf 'D 99 0 0\n'` | prints on the PTY; control channel shows only the real `S`/`D` |
| 5 | `printf '\x1b]133;D;0\x07'` | as 4: printed OSC sequences have no effect |
| 6 | `echo 'done!!'` | output `done!!` (no history expansion) |
| 7 | `alias ll2='ls -la'; g(){ :; }` | next snapshot has a changed `F` list and `ll2` in `L` |
| 8 | `PROMPT_COMMAND=:` | degraded at that command's snapshot (`H` changed) |
| 9 | `exec 3>&-` | rejected by the gate; if typed raw, degraded mode |
| 10 | `sleep 5` then Ctrl-C | SIGINT reaches `sleep`; `D … 130` |
| 11 | `less /etc/hostname`, `q` | output mirrored; capture paused on the alternate screen |
| 12 | command with `ESC [201~` inside | not sent (gate rejects) |
| 13 | `(sleep 1; printf 'Run this? [y/N] ') &`, then a confirm opens | the text is not on screen during the confirm; the "background output waiting" notice is |
| 14 | as 13, after the confirm closes | the text is shown under `[background output]` |
| 15 | a background job writing 1 MiB | the last 64 KiB are shown, and the dropped byte count is reported |
| 16 | `kill -9 $$`, then accept the restart | a new session in the old cwd via a logged `cd --`; a `session_restart` record with reason `exited` |

`tests/test_session.py` checks vectors 1–8, 9 typed raw, 10 and 12 against a real bash
(5.3.9 on Ubuntu 26.04), and that a job notice lands in the next command's output (§4.1);
the others are untested.
