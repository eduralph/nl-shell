# Spec: PTY session protocol -- v1

> Normative specification. **Status: DRAFT (unstable -- will change).** This document uses
> [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) keywords: MUST, SHOULD, MAY.
> Decision record: ADR-0014.

## Motivation

The REPL, the policy gate (spec `policy-gate/v1`) and the sudo handling (ADR-0015) all
depend on knowing exactly when a command starts and ends, its exit status, and the state
of the bash session. That knowledge must not be forgeable by anything a command prints.

## Scope

Covers: how the session is started, the control-channel record format, the session
snapshot, how a confirmed command is sent, terminal ownership while a command runs, and
degraded mode. Does not cover: what is classed how (policy-gate spec), sudo prompt
handling (ADR-0015), or what captured output is used for (taint, ADR-0016).

## Conventions

- *Session*: one bash process on a PTY, started by nl-shell, for the life of the REPL.
- *Control channel*: a pipe whose write end is file descriptor 3 in the session.
- *Record*: one line on the control channel, `\n`-terminated, fields separated by one
  space, first field a one-letter type.

## Requirements

### 1. Starting the session

1. nl-shell MUST start `bash --noprofile --rcfile <rcfile> -i` on a PTY, with the write end
   of a pipe as fd 3 in the child and the read end kept by nl-shell.
2. The rcfile MUST source the user's `~/.bashrc` (if present) **before** installing
   nl-shell's hooks, and MUST:
   - turn off history expansion (`set +H`);
   - unset `HISTFILE` (nl-shell writes history itself, ADR-0014 §5);
   - save any `PROMPT_COMMAND` set by `~/.bashrc` (every element) and run it at every
     prompt after the `D` record and **before** the snapshot, so the snapshot sees what it
     changed; nl-shell's hook is the last `PROMPT_COMMAND` element;
   - set `PS1` and `PS2` to fixed values after the user's `PROMPT_COMMAND` and again after
     the snapshot, unless a command gave them attributes (such as `readonly`), which `H`
     shows (§3);
   - make `PS4` `readonly` after `~/.bashrc` is sourced: bash traces `PROMPT_COMMAND`
     itself, so a `PS4` set by a command would be expanded (and could run code) before any
     snapshot could see it. This is a user-visible change: a confirmed `PS4=…` (or
     `declare PS4=…`, `printf -v PS4 …`) fails with "readonly variable". `PS4` keeps the
     value `~/.bashrc` gave it;
   - unset `MAILCHECK` and make it `readonly` after `~/.bashrc` is sourced, so bash never
     checks mail: it does so after `PROMPT_COMMAND`, just before readline takes the
     terminal, and expands the message text of a `MAILPATH` entry, so code could run there
     after every check below. This is a user-visible change: the session never prints
     "You have mail", and a confirmed `MAILCHECK=…` fails with "readonly variable";
   - if `~/.bashrc` already made `PS4` or `MAILCHECK` `readonly`, so the pin above cannot
     be told from the user's own, define a function `nl_shell_unpinned_<name>`; nl-shell
     finds it in the baseline's `F` and the session starts degraded with a reason naming
     the variable;
   - capture stderr (`2>&1`) in every command substitution in the hooks, so a failing or
     disabled builtin never yields an empty value that matches the baseline;
   - return at once from a hook function whose first `\builtin set` fails (`set` or
     `builtin` disabled), so no record is written and the prompt rule (§4.2) applies;
   - set `PS0` and `PROMPT_COMMAND` as in the reference rcfile below.
3. Reference rcfile (tested on bash 5.1, 5.2 and 5.3, the supported releases: CI builds
   each with `scripts/build_bash.py`; `src/nl_shell/session.py` `RCFILE`, and
   `tests/test_session.py` checks the two are the same):

```bash
[ -f ~/.bashrc ] && . ~/.bashrc
set +H
unset HISTFILE
for __nls_c in PS4 MAILCHECK; do
  __nls_v=$(declare -p "$__nls_c" 2>/dev/null); __nls_v=${__nls_v#declare -}
  if [[ ${__nls_v%% *} == *r* ]]; then eval "nl_shell_unpinned_$__nls_c() { :; }"; fi
done
readonly PS4
unset MAILCHECK 2>/dev/null; readonly MAILCHECK
bind 'set enable-bracketed-paste on' 2>/dev/null
shopt -s promptvars
__nls_ea=$(shopt -p expand_aliases); shopt -u expand_aliases
__nls_user_pc=()
if declare -p PROMPT_COMMAND >/dev/null 2>&1; then __nls_user_pc=("${PROMPT_COMMAND[@]}"); fi
__nls_seq=-1 __nls_st=0 __nls_ps=() __nls_v= __nls_c= __nls_n=0 __nls_pre=
PS0='$(\\builtin printf "S %s\\n" "$((__nls_seq + 1))" >&3)'
__nls_ret() { \builtin return "$1"; }
__nls_enc() {
  __nls_v=$2
  __nls_v=${__nls_v//'\'/'\\'}
  __nls_v=${__nls_v//$'\n'/'\n'}
  __nls_v=${__nls_v//$'\r'/'\r'}
  \builtin printf '%s %s\n' "$1" "$__nls_v" >&3
}
__nls_done() {
  \builtin set -- "$?" "${PIPESTATUS[@]}" || return
  __nls_pre=$(\builtin declare -p __nls_pre __nls_c __nls_n __nls_ps __nls_st __nls_v 2>&1) ||
    \builtin :
  __nls_st=$1
  \builtin shift
  __nls_ps=("$@")
  \builtin jobs -n
  \builtin printf '\033]7700;@NLS_END@\007'
  __nls_seq=$((__nls_seq + 1))
  \builtin printf -v __nls_v ' %s' "${__nls_ps[@]}"
  \builtin printf 'D %s %s%s\n' "$__nls_seq" "$__nls_st" "$__nls_v" >&3
  for __nls_c in "${__nls_user_pc[@]}"; do
    if __nls_ret "$__nls_st"; then
      \builtin eval "$__nls_c" || \builtin :
    else
      \builtin eval "$__nls_c" || \builtin :
    fi
  done
  __nls_st=0 __nls_ps=() __nls_v= __nls_c= __nls_n=0
}
__nls_snap() {
  \builtin set -- "$1" "${BASHOPTS-}" || return
  \builtin shopt -u expand_aliases
  for __nls_c in PS1 PS2; do
    __nls_v=$(\builtin declare -p "$__nls_c" 2>&1) || __nls_v=
    if [[ -z $__nls_v || ${__nls_v%%=*} == "declare -"[-x]" $__nls_c" ]]; then
      if [[ $__nls_c == PS1 ]]; then PS1='\$ '; else PS2='> '; fi
    fi
  done
  __nls_v=$(\builtin trap -p EXIT 2>&1) __nls_c=
  __nls_enc H "$( {
    [[ $__nls_v == "trap -- "* ]] || __nls_v=
    __nls_c=${1#"$__nls_v"}
    \builtin printf 'traps but EXIT:\n%s\n' "${__nls_c#$'\n'}"
    __nls_v= __nls_c=
    \builtin declare -p PS0 PROMPT_COMMAND __nls_user_pc TERM PS1 PS2 PS4 MAILCHECK
    \builtin shopt -p promptvars
    \builtin shopt -p extdebug || \builtin :
    \builtin shopt -po emacs vi functrace errtrace xtrace histexpand || \builtin :
    for __nls_c in BASH_XTRACEFD __nls_c __nls_done __nls_ea __nls_enc __nls_n __nls_pre __nls_ps __nls_ret __nls_seq __nls_snap __nls_st __nls_user_pc __nls_v; do
      \builtin declare -p "$__nls_c" 2>&1 || \builtin printf '%s unset\n' "$__nls_c"
    done
    \builtin declare -f __nls_done __nls_snap __nls_enc __nls_ret
    \builtin declare -pF __nls_done __nls_snap __nls_enc __nls_ret
    for __nls_c in ':' 'alias' 'bind' 'compgen' 'declare' 'enable' 'eval' 'jobs' 'printf' 'return' 'set' 'shift' 'shopt' 'trap' 'builtin'; do
      \builtin compgen -A disabled -X "!$__nls_c" -- "$__nls_c" || \builtin :
    done
    __nls_v=$(\builtin bind -v 2>&1)
    __nls_c=${__nls_v#*$'\n'set history-size }
    __nls_v=${__nls_v/$'\n'"set history-size ${__nls_c%%$'\n'*}"$'\n'/$'\n'}
    \builtin printf '%s\n' "$__nls_v"
    for __nls_c in emacs-standard emacs-meta emacs-ctlx vi-command vi-insert; do
      \builtin bind -m "$__nls_c" -p
      \builtin bind -m "$__nls_c" -s
      \builtin bind -m "$__nls_c" -X
    done
  } 2>&1 )"
  __nls_enc V "$(
    for __nls_c in PAGER MANPAGER SYSTEMD_PAGER GIT_PAGER LESSOPEN LESSCLOSE LD_PRELOAD LD_LIBRARY_PATH BASH_ENV ENV; do
      \builtin declare -p "$__nls_c" 2>&1 || \builtin printf '%s unset\n' "$__nls_c"
    done 2>&1
  )"
  __nls_enc F "$(\builtin compgen -A function 2>&1)"
  __nls_enc L "$(\builtin alias -p 2>&1)"
  __nls_enc T "$1"
  __nls_enc B "$(\builtin enable -n 2>&1)"
  __nls_enc X "$(\builtin shopt -p extdebug 2>&1)"
  __nls_enc P "${PATH-}"
  __nls_v=$(\builtin jobs -ps 2>&1) __nls_n=0
  if [[ -n $__nls_v ]]; then __nls_c=${__nls_v//[!$'\n']/}; __nls_n=$((${#__nls_c} + 1)); fi
  \builtin printf 'J %s\n' "$__nls_n" >&3
  __nls_st=0 __nls_ps=() __nls_v= __nls_c= __nls_n=0 __nls_pre=
  \builtin printf 'E\n' >&3
  PS1='\$ ' PS2='> '
  if [[ :$2: == *:expand_aliases:* ]]; then \builtin shopt -s expand_aliases; fi
}
\builtin unset PROMPT_COMMAND
PROMPT_COMMAND=('' '\__nls_done; \__nls_snap "$(\builtin trap -p 2>&1)"')
builtin eval "$__nls_ea"; builtin unset __nls_ea
```

   The hooks call no external program, only bash builtins and parameter expansion.
   `PS0` writes `\\n` because bash decodes prompt escapes before expanding `PS0` and would
   turn `\n` into CR LF. `PROMPT_COMMAND` element 0 is empty (it keeps `$?` and
   `PIPESTATUS`), so `PROMPT_COMMAND=:` replaces it and leaves nl-shell's hook in place.
   `@NLS_END@` is replaced by a random token at every start: `__nls_done` prints that OSC
   sequence on the PTY before it writes `D` and before the user's `PROMPT_COMMAND` runs,
   and a command's output is what follows readline's end of the paste (`ESC [?2004l`) and
   precedes that marker. Just before that marker `__nls_done` runs `jobs -n`, which prints
   the notices of jobs that changed state since bash last reported them: bash 5.3 prints
   them before `PROMPT_COMMAND` runs, but bash 5.2 prints them after it, past the marker,
   where they would be lost. The hooks are safe under `set -u` and `set -e`.

   **What this protects.** This is a closed list; nothing else is claimed (#145 reviews
   what else can evade the hooks).
   - A command that ran is never reported as "nothing ran" while the session stays
     healthy, for: ordinary commands; a confirmed command that changes anything `H`
     covers (§3), which degrades at that command's own snapshot; a `PS1` that assigns hook
     state as a side effect, `readonly` on hook state, and a top-level `trap … DEBUG`
     that assigns hook state; and user aliases, which cannot change what the hooks run
     (every command word in `PS0`, `PROMPT_COMMAND` and `__nls_done` is `\builtin`-quoted,
     and `__nls_snap` runs its `$( … )` bodies with `expand_aliases` off).
   - Of `PROMPT_COMMAND`, `PS0`, `PS1` and `PS2`: nl-shell's hook is the last
     `PROMPT_COMMAND` element, the user's elements from `~/.bashrc` run inside it before
     the snapshot, and a confirmed change to the value of a plain or exported `PS1`/`PS2`
     is overwritten by nl-shell before it is shown. A confirmed change to `PS0` or
     `PROMPT_COMMAND`, or to the attributes of `PS1`/`PS2` (such as `readonly`), degrades
     at that command's own snapshot (`H`), but the code it set may still run once after
     that snapshot; the session is degraded by then, so no paste follows it.
   - The bytes bash runs for a paste are the confirmed bytes, or nothing is sent (I1),
     against these changes made by a confirmed command, by code it planted in a trap or
     in a function a user `PROMPT_COMMAND` element calls, or by a `PROMPT_COMMAND` from
     `~/.bashrc`. The check comes in two parts:
     1. Bash state, read in `H` (§3) after the last code that can run synchronously
        before readline takes the terminal, and degrading at that command's own snapshot:
        every trap but `EXIT` (signal traps too, as they can run while readline waits),
        `extdebug`, `functrace`, `errtrace`, `xtrace`, `BASH_XTRACEFD` and `PS4` (which is
        `readonly`, see above); history expansion (`set -H`); disabling a builtin the
        hooks call (`HOOK_BUILTINS` in `src/nl_shell/session.py`); readline turned off,
        its editing mode, its variables (except `history-size`, which follows `HISTSIZE`),
        and every key binding (functions, macros, `bind -x`) in the `emacs-standard`,
        `emacs-meta`, `emacs-ctlx`, `vi-command` and `vi-insert` keymaps.
     2. The whole terminal state while readline holds the terminal, read from outside
        bash just before every paste, and bash's fds 0, 1 and 2 (`exec >/dev/null`); a
        difference degrades the session and the paste is not written (§3, outside
        checks).

     The shell's own values of the terminal fields readline sets itself while it reads a
     line (R, §3) are not checked (#149): they cannot change the bytes readline reads from
     a paste, because readline sets them itself while it reads, but the commands after a
     change run with it (no Ctrl-C, no echo, …) and the session does not degrade.

     Besides what a command changes: a stopped shell degrades the session, and a system
     that allows TIOCSTI starts it degraded. Bash's mail check is not seen but turned off
     for good (`MAILCHECK` unset and `readonly`, see above), so a `MAILPATH` message, set
     by `~/.bashrc` or by a command, never runs code. A session whose `~/.bashrc` turns
     on `functrace` (`set -T`, or `extdebug`), already made `PS4` or `MAILCHECK`
     `readonly`, or gave `PS1`/`PS2` an attribute nl-shell cannot reset (such as
     `readonly`) starts degraded: a DEBUG trap set later could hide itself from the
     snapshot, `PS4` or the mail check could run code nl-shell cannot see, or `PS1` is
     expanded after the snapshot. Disabling `set`, `printf` or `builtin` stops the records
     (both hook functions return at once when their first `\builtin set` fails); the
     prompt rule (§4.2) then degrades the session. The gaps that remain are listed in the
     threat model (`.oss-scanner/threat_model.md`, Known gaps).

### 2. Records

| Record | Written by | Fields | Meaning |
|---|---|---|---|
| `S <n>` | `PS0` | sequence number of the command about to run | a command started |
| `D <n> <status> <pipestatus…>` | `PROMPT_COMMAND` | sequence number, `$?`, `PIPESTATUS` | the command finished, or nothing ran (§4.1) |
| `F <names>` | `PROMPT_COMMAND` | `compgen -A function` output, encoded | function names, one per line |
| `L <defs>` | `PROMPT_COMMAND` | `alias -p` output, encoded | alias definitions |
| `E` | `PROMPT_COMMAND` | — | end of this snapshot |

The first snapshot (before any command) has sequence number 0 and no `S` record.

Every free-text field (`F`, `L` and the §3 text fields) uses one reversible encoding: `\`
is written `\\`, LF `\n` and CR `\r`; no other escape exists, so a record never holds a
raw LF or CR. A record that contains a CR, or a bad escape, is malformed.

### 3. Snapshot (v1 fields)

Besides `F` and `L`, a v1 snapshot MUST carry, as separate record types before `E`:
`T` (output of `trap -p`), `B` (output of `enable -n`, i.e. disabled builtins), `X`
(`shopt -p extdebug`), `P` (`$PATH`), `J` (number of stopped jobs, counted from
`jobs -ps` with builtins only), `H` and `V`. nl-shell records the first snapshot as the
session's **baseline**.

`H` and `V` carry raw `declare -p` (and builtin) output text, encoded as in §2, and are
compared exactly; there is no checksum.

- `H` covers nl-shell's prompt hooks and their state: `declare -p` of `PS0`,
  `PROMPT_COMMAND` (every element), the saved user hook, `TERM` (readline turns bracketed
  paste off for some terminals), and `PS1` and `PS2` as nl-shell set them; `shopt -p
  promptvars`; `declare -p` of every hook state variable, value and attributes (so
  `readonly` too; `NAME unset` when it is not a variable); and `declare -f` of the hook
  functions. The hooks overwrite their scratch variables, so `__nls_done` first saves
  their `declare -p` text in `__nls_pre` (part of `H`) and `__nls_snap` resets them before
  `E`; a confirmed change to their value or attributes shows in that command's `H`. The
  only value that changes between snapshots is the sequence counter, which MUST equal the
  `D` record's number. Everything else MUST equal the baseline byte for byte.
- `H` also covers what can make bash run code, or change what a paste does, after the
  snapshot:
  - every trap but `EXIT`: `trap -p`, read at the top level of nl-shell's
    `PROMPT_COMMAND` element and passed to `__nls_snap` (inside an untraced function bash
    does not show the DEBUG, RETURN and ERR traps), after the last DEBUG trap run for that
    element. The `EXIT` trap (`trap -p EXIT`) is cut off the front of that list, as it
    only runs when bash exits. A signal trap is here because it can run while readline
    waits for the next line, after every check; a CHLD trap runs each time a `$( … )` of
    the hooks ends, so also after `H` is read. `T` still reports the full list;
  - `shopt -p extdebug`; `set -o` state of `emacs`, `vi`, `functrace`, `errtrace`,
    `xtrace` and `histexpand`; `declare -p` of `PS4`, `MAILCHECK` and `BASH_XTRACEFD`;
  - `declare -F` of the hook functions (their attributes, such as the trace attribute);
  - which of the builtins the hooks call are disabled (`HOOK_BUILTINS`: every name the
    hook functions, `PS0` and nl-shell's `PROMPT_COMMAND` element call as `\builtin
    <name>`, plus `builtin`). Other disabled builtins are only reported, in `B`;
  - `bind -v` without its `history-size` line (it follows `HISTSIZE` and cannot change
    paste bytes), and `bind -p`, `bind -s` and `bind -X` for the `emacs-standard`,
    `emacs-meta`, `emacs-ctlx`, `vi-command` and `vi-insert` keymaps. The
    locale-dependent variables (`convert-meta`, `input-meta`, `output-meta`) are kept, so
    a command that changes the locale (`LC_ALL=C`) degrades the session.

  `H` is read after the user's `PROMPT_COMMAND` elements have run, so a change any of
  them makes shows in it. Of the code that can run after `H` is read, a trap and a key
  binding only run if what makes them run is in `H`; bash's mail check, which runs after
  `PROMPT_COMMAND`, is off (§1.2). A trap or a `bind -x` binding set by `~/.bashrc` is in
  the baseline, so `H` does not change for it, yet it can call a function a confirmed
  command redefines (`F` is only reported): a known gap (#150).
- `V` is `declare -p` of the pager and loader variables listed in spec `policy-gate/v1`
  §7.5 (`NAME unset` when unset).
- `F`, `L`, `T`, `B`, `X`, `P` and `J` are reported to the gate; a change to them does not
  degrade the session.

**Outside checks.** The terminal settings are not bash state, so nl-shell reads them from
outside bash (`tcgetattr` on the PTY master), with what bash's fds 0, 1 and 2 are
(`/proc/<pid>/fd` and `fdinfo`: the file and its access mode). While readline reads a line
it sets some terminal fields itself, and puts the shell's own values back when the line is
accepted. These fields are **R**: in `c_lflag`, `ISIG` on and `ICANON`, `ECHO` and
`FLUSHO` off; in `c_iflag`, `ICRNL`, `INLCR`, `ISTRIP` and `INPCK` off; in `c_cc`, `VMIN`
1, `VTIME` 0, and `VLNEXT` and `VDISCARD` disabled (readline's `rltty.c`,
`prepare_terminal_settings`, and measured on bash 5.3.9; Linux never keeps `FLUSHO` set,
so it always reads off; readline disables `VDISCARD` only when its key is bound to a
readline function, as `\C-o` is by default, and leaves `IXON` alone on bash 5.3.9;
it turns `ISTRIP` and `INPCK` off only when `CSIZE` is `CS8` or its meta flag is set; a
Linux PTY keeps `CSIZE` at `CS8` whatever `stty` asks, any other `CSIZE` would differ in
check 1, and a change to `input-meta` shows in `H`). A
reading taken while readline holds the terminal sees R as readline sets it, never as the
shell's own settings have it; and the shell's own values of R cannot change the bytes
readline reads from a paste, only how a command runs after it.

1. Just before every paste, while readline holds the terminal (bash blocked as in §4.2),
   every field, R included, is compared with a reading taken in the same state at the
   first prompt; at start, R in that reading must have readline's values (`VDISCARD`
   aside, see above), or the session starts degraded. Fields outside R carry the shell's own settings, so a confirmed
   `stty intr '|'` shows here. A difference in R means something changed the terminal
   while readline held it (a background job's `stty -isig`, say). bash's fds 0, 1 and 2
   are compared with the first prompt's too. Any difference degrades the session and the
   paste is not written. A change made between this reading and the write is a known gap
   (#147).
2. At each `E`, bash's fds 0, 1 and 2 are compared with the first prompt's, before the
   command's output is read (with fd 1 redirected the end marker never arrives). bash
   writes `E` with `printf 'E\n' >&3`, so just after `E` arrives its fd 1 can still be
   the control pipe. A reading that differs is taken again once readline waits for a
   line (the redirect is then undone), or once the prompt wait runs out, and only that
   second reading degrades the session.

The shell's own values of R are not checked (#149). Every reading nl-shell can take
without bash waiting for it either sees R as readline sets it or depends on nl-shell being
scheduled inside a short window, so it would miss changes or raise false alarms. These
values cannot change the bytes of a paste. A command (or a trap, or a background job while
a command runs) can still change them, and the commands after it run with the change while
the session stays healthy; in particular with `ISIG` off, `Session.interrupt()` (which
writes `\x03`) no longer interrupts a command, so a `run()` without a timeout can hang on
a runaway command.

These checks need Linux `/proc`. None of them has bash wait for nl-shell, and none
depends on nl-shell being scheduled inside a window bash does not wait for.

### 4. Sequencing and degraded mode

1. After sending a command, nl-shell MUST see `S n+1`, then `D n+1 …`, then a snapshot
   ending in `E`, in that order. Output on the PTY between `S` and `D` belongs to that
   command; it includes bash's job notices (`[1]+  Done …`), which bash or the hook's
   `jobs -n` (§1.3) prints after the command and before `D`, so a background job's
   notice lands in the output of a later command.
   `PS0` runs once per line of a multi-line command, so `S n+1` MAY repeat before `D n+1`.
   `D n+1` without `S n+1` means bash read the input but ran nothing (an empty line, a
   comment, a syntax error): it is reported as not run with the `D` status, and the
   session stays healthy.
2. nl-shell MUST enter **degraded mode** when:
   - a record is missing, out of order or malformed (except `D n+1` without `S n+1`,
     §4.1);
   - the control channel closes;
   - from the paste, no `D` has arrived and bash has been blocked reading fd 0 (read from
     `/proc/<bash pid>/syscall`; fd 0 is the session's PTY slave or `/dev/tty`, so a
     builtin reading a redirected fd 0 does not count) for 1 s continuously: "no done
     record after the shell returned to a prompt". nl-shell does not parse the PTY stream
     for prompts. If `/proc/<bash pid>/syscall` cannot be read, at start or during a
     command, the session degrades with a reason naming the file. Known limits (#136): a
     terminal read on another fd (`read -u 2 x`) is not seen, so a `run()` with no
     timeout can wait forever; timed or single-key reads (`read -t`, `read -n1 -t`) and
     `select` degrade even when they would finish;
   - the snapshot's `H` differs from the baseline (nl-shell's hooks were changed); this is
     found at the snapshot of the command that changed them;
   - an outside check (§3) differs from the baseline, or cannot be made (`/proc/<pid>/fd`,
     `fdinfo` or the terminal settings cannot be read): the terminal settings before a
     paste, or bash's fds 0-2 before a paste or at `E`;
   - bash is stopped (state `T` or `t` in `/proc/<pid>/stat`), checked before every paste
     and at every poll while nl-shell waits for a command's records or for the prompt;
   - at start, the kernel allows TIOCSTI: `/proc/sys/dev/tty/legacy_tiocsti` is missing,
     unreadable or not `0` (another process on the terminal could push input into it);
   - at start, `functrace` is on after `~/.bashrc`, `~/.bashrc` already made `PS4` or
     `MAILCHECK` `readonly`, `PS1` or `PS2` has an attribute nl-shell cannot reset (§1.3),
     or R at the first prompt does not have readline's values (§3).

   Every degrade carries a reason (text for the user) and a fixed code saying which check
   fired: `h-changed` (`H` differs), `missing-record` (a snapshot record missing, or the
   prompt rule), `exited` (bash exited), `outside-check`, `stopped`, `tiocsti`, and
   `other` for the rest (`Session.degraded_code`, `SessionDegraded.code`).
3. In degraded mode nl-shell MUST NOT send the session any further command until it is
   restarted. The user MUST be told why, and nl-shell MUST offer to restart the session.
4. **Session recovery.** When bash exits unexpectedly or the user accepts a restart,
   nl-shell starts a new session and restores the last cwd with a visible, logged
   `cd -- <path>` if that path still exists. Shell variables, aliases, functions and jobs
   are not restored; nl-shell says so in one line. Restoring the cwd lands with #121;
   until then a restart gives a fresh session and baseline only.
5. The session log records the restart as a turn with `"decision": "none"` and the field
   `"event": {"type": "session_restart", "reason": …}`, where the reason is `exited`,
   `degraded` or `user` (spec `session-log/v1`). This record lands with #121.

### 5. Sending a command

1. nl-shell MUST send exactly the confirmed bytes as one bracketed paste
   (`ESC [200~` … `ESC [201~`) followed by a single `CR`.
2. A command containing `ESC`, any other C0 control character except TAB and LF, or the
   byte sequence `ESC [201~` MUST NOT be sent (the policy gate rejects it first).
3. Nothing else may be sent to the session while a command runs, except forwarded
   keystrokes (§6).

### 6. Terminal ownership

1. Between sending a command and its `D` record, nl-shell MUST put the real terminal in
   raw mode and forward every input byte to the PTY master unchanged, and MUST NOT log,
   capture or keep any forwarded input byte.
2. nl-shell MUST copy PTY output to the real terminal and MAY capture it for the state
   block, subject to:
   - capture MUST stop on `ESC [?1049h` / `ESC [?47h` (alternate screen) and resume on
     the matching reset;
   - capture MUST stop during sudo passthrough (ADR-0015).
3. On `SIGWINCH`, nl-shell MUST copy the real terminal's size to the PTY.
4. Ctrl-C, Ctrl-Z and other control keys travel as bytes; nl-shell MUST NOT intercept
   them while a command runs.
5. At the prompt (after `E`), prompt_toolkit owns the terminal.
6. **Background output.** A job started earlier with `&`, or a process still attached to
   the PTY, can keep writing while prompt_toolkit owns the terminal. Its output could cover
   the confirm or imitate a confirm or a sudo prompt, so:
   - Between a done record and the next start record (prompt_toolkit owns the terminal),
     bytes read from the PTY MUST NOT reach the screen directly. nl-shell buffers them, up
     to 64 KiB, dropping the oldest bytes beyond that and saying how many were dropped.
   - The buffer is shown above the prompt, through the same output filter as mirrored
     output, under a line `[background output]`, when the user is not in a confirm and not
     editing a line, or on `:jobs`.
   - During a confirm the buffer is never shown. The confirm shows a one-line notice
     "background output waiting" instead, so the user knows something is running.
   - Background output is labelled untrusted and is never added to the state block.

   The 64 KiB limit is a starting value, to be adjusted after M0 dogfooding.

### 7. History

nl-shell MUST append each executed command to `~/.bash_history` itself, after the `D`
record, and record the turn's taint in the session log (ADR-0016). The session MUST NOT
write history.

## Versioning and compatibility

Adding a snapshot record type is compatible within v1 if nl-shell ignores unknown types.
Changing a record's fields, the paste framing or the start-up command requires v2.
While this spec is `status: draft`, v1 changes in place; the v2 rule applies once it is
`stable`.

## Conformance

The session tests for #10 (#101, #102, #120, #121) MUST cover at least these vectors:

| # | Sent | Expected on the control channel / behaviour |
|---|---|---|
| 1 | `true` | `S 1`, `D 1 0 0`, snapshot, `E` |
| 2 | `false \| true` | `D … 0 1 0` |
| 3 | `(exit 3)` | `D … 3 3` |
| 4 | `printf 'D 99 0 0\n'` | prints on the PTY; control channel shows only the real `S`/`D` |
| 5 | `printf '\x1b]133;D;0\x07'` | as 4: printed OSC sequences have no effect |
| 6 | `echo 'done!!'` | output `done!!` (no history expansion) |
| 7 | `alias ll2='ls -la'; g(){ :; }` | next snapshot has a changed `F` list and `ll2` in `L` |
| 8 | `PROMPT_COMMAND=:` | degraded at that command's snapshot (`H` changed) |
| 9 | `exec 3>&-` | rejected by the gate; if typed raw, degraded mode |
| 10 | `sleep 5` then Ctrl-C | SIGINT reaches `sleep`; `D … 130` |
| 11 | `less /etc/hostname`, `q` | output mirrored; capture paused on the alternate screen |
| 12 | command with `ESC [201~` inside | not sent (gate rejects) |
| 13 | `(sleep 1; printf 'Run this? [y/N] ') &`, then a confirm opens | the text is not on screen during the confirm; the "background output waiting" notice is |
| 14 | as 13, after the confirm closes | the text is shown under `[background output]` |
| 15 | a background job writing 1 MiB | the last 64 KiB are shown, and the dropped byte count is reported |

`tests/test_session.py` checks vectors 1–8, 9 typed raw, 10 and 12 against a real bash
