# Spec: Quarantined reader output -- v1

> Normative specification. **Status: DRAFT (unstable -- will change).** This document uses
> [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) keywords: MUST, SHOULD, MAY.
> Decision records: ADR-0017 (reader), ADR-0018 (serving).

## Motivation

The reader reads text an attacker may have written. What it returns is the only channel
from that text to the command model, so the channel has to be as narrow as the use case
allows: fixed choices and names that already exist on the system, no free text.

## Scope

The error-diagnosis answer used by fix-on-failure (#17) and `?why` (#14) after a failed
command (#61). Not covered: other reader tasks, which need their own schema versions.

## Requirements

1. The response MUST be one JSON object matching this schema, enforced by constrained
   decoding:

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["category"],
  "properties": {
    "category": { "enum": ["not-found", "permission", "syntax", "missing-package",
                           "missing-file", "service-failed", "network", "disk-full",
                           "busy-or-locked", "unknown"] },
    "missing": { "type": "array", "maxItems": 3,
                 "items": { "type": "string", "pattern": "^[a-z0-9][a-z0-9.+@_-]{0,62}$" } },
    "unit": { "type": "string", "pattern": "^[A-Za-z0-9@._-]{1,128}\\.(service|socket|timer|mount|target)$" }
  }
}
```

2. **Validation after decoding** (the schema alone is not enough):
   - every `missing` value MUST be a package name in the local apt/dpkg index, or a
     command provided by an indexed package; values that aren't are dropped;
   - `unit` MUST appear in `systemctl list-unit-files` output, or it is dropped.
3. A response that fails to parse or fails the schema MUST be rejected, and the REPL then
   proceeds with "no diagnosis" (ADR-0017 §3).
4. The REPL builds every message the user sees from templates keyed on `category`, with
   the validated `missing` and `unit` values filled in. There is no free-text field.
5. The result is labelled `untrusted` (ADR-0016) when it enters the state block.

## Versioning and compatibility

Adding a `category` value is compatible if the REPL treats unknown values as `unknown`.
Adding a free-text field is not allowed in any version without a new ADR superseding
ADR-0017.

## Conformance

#61's tests MUST include:
- each category;
- `missing` with a real package, a non-existent package and a shell-metacharacter string;
- `unit` with a real and an unknown unit;
- extra properties;
- invalid JSON;
- a response that tries to place an instruction anywhere (it can't validate).

## Open questions

- Whether `category` alone is too coarse for `service-failed` diagnoses; a later version
  may add a fixed-choice `cause` field.
