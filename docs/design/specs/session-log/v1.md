# Spec: Session log -- v1

> Normative specification. **Status: DRAFT (unstable -- will change).** This document uses
> [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) keywords: MUST, SHOULD, MAY.
> Decision records: ADR-0014 (completion), ADR-0016 (taint), ADR-0020 (location).

## Motivation

The session log is written by the REPL (#18) and read by history retrieval (#79), the eval
and classifier material (#30) and debugging. `docs/plan.md`'s example record had taint per
record rather than per item, and used `exit` twice with different meanings. A second
reader depends on the format, so it is a spec.

## Scope

One JSONL file per session under `$XDG_STATE_HOME/nl-shell/sessions/` (ADR-0020), one
record per turn. Not covered: what is scrubbed before writing (#20 decides it; this spec
requires that it happens).

## Requirements

1. Each line MUST be one JSON object with these fields:

| Field | Type | Meaning |
|---|---|---|
| `v` | `1` | spec version |
| `ts` | string, RFC 3339 with offset | when the turn started |
| `seq` | integer | the control-channel sequence number of the command run, or `null` if nothing ran |
| `input` | object | `{"mode": "plain"\|"raw"\|"ask"\|"one"\|"agent"\|"meta", "text": string}`: what the user typed |
| `context` | array | the items sent to the model for this turn: `{"kind": string, "label": "trusted"\|"local-reference"\|"untrusted", "value": string}` |
| `proposal` | object or `null` | the parsed proposal (spec `proposal/v1`), or `null` |
| `clean_room` | boolean | whether the proposal was re-derived from trusted context (ADR-0016) |
| `gate` | object | `{"class": string, "reasons": [string], "rejected": boolean}` |
| `decision` | `"ran"`\|`"edited"`\|`"declined"`\|`"rejected"`\|`"none"` | what happened |
| `final` | string or `null` | the exact bytes sent to the session, if any |
| `final_by_user` | boolean | `final` came from the user's own input or edit (ADR-0015 §8) |
| `exit` | integer or `null` | the command's exit status from the `D` record (spec `pty-protocol/v1`) — the only exit field |
| `pipestatus` | array of integers | from the `D` record |
| `tainted` | boolean | true if any `context` item was `untrusted`; history retrieval skips these turns (ADR-0016 §4) |
| `passthrough` | boolean | sudo passthrough happened; captured output for that span is absent |
| `sudo_cache_warm` | boolean | the sudo credential cache was warm when the confirm was shown (ADR-0015 point 6) |

2. Captured output MUST NOT be stored verbatim. `context` holds only the (truncated,
   scrubbed) items that were sent to the model.
3. Nothing typed during a running command (forwarded keystrokes, ADR-0014) MAY appear in
   any field.
4. Secrets MUST be scrubbed per #20 before a record is written. Directory mode `0700`,
   file mode `0600`.

## Versioning and compatibility

Adding a field is compatible within v1; readers MUST ignore unknown fields. Renaming or
removing a field, or changing a type, requires v2.

## Conformance

#18's tests MUST check: a record per turn; that `exit` matches the `D` record; that
`tainted` is true when any context item is untrusted; that a sudo passthrough turn has
`passthrough: true` and contains no password sentinel anywhere; and the file modes.

## Open questions

- Retention: how long logs are kept, and whether `:history` offers deletion.
